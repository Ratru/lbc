# PDF Receipt Editor Bot — Документация проекта

## Описание

Telegram-бот для редактирования текстовых полей в PDF-квитанциях Т-Банка.
Бот проводит пользователя по всем полям пошагово, сохраняя шрифт TinkoffSans,
размеры, цвета, позиции и выравнивание текста из документа.

## Сценарий работы бота

```
Пользователь → отправляет PDF
Бот → извлекает текстовые блоки из документа
Бот → пошагово спрашивает каждое поле (показывает текущее значение)
Пользователь → вводит новое значение или нажимает ⏭ Пропустить
Бот → экран подтверждения со всеми изменениями
Пользователь → нажимает ✅ Сохранить PDF
Бот → отправляет готовый PDF
```

## Поддерживаемые шаблоны квитанций

Бот определяет тип квитанции автоматически (по наличию метки
«Карта получателя» либо «Телефон получателя»):

| Шаблон | Тип перевода | Поле получателя |
|--------|--------------|-----------------|
| 1 | По номеру карты | «Карта получателя» |
| 2, 3 | По номеру телефона (СБП) | «Телефон получателя» |

Шаблоны 2 и 3 идентичны по структуре. В квитанции по телефону есть также
поля «Счёт списания» и «Идентификатор операции / СБП» — бот их не меняет,
они переносятся из оригинала без изменений.

## Редактируемые поля

| Поле | Особая логика |
|------|---------------|
| Дата | Вводится отдельно (ДД.ММ.ГГГГ) |
| Время | Вводится отдельно (ЧЧ:ММ:СС) |
| Сумма | Автоматически обновляет и «Итого» |
| Отправитель | Свободный текст |
| Карта получателя *(шаблон 1)* | Вводят 16 цифр → `XXXXXX******XXXX` |
| Телефон получателя *(шаблоны 2/3)* | Вводят 10 цифр или `+7…` → `+7 (XXX) XXX-XX-XX` |
| Получатель | Свободный текст (напр. `Иван И.`) |
| Банк получателя | Свободный текст |
| Квитанция № | Только номер, префикс «Квитанция №» добавляется автоматически |

Шаг «Карта / Телефон» один — бот сам показывает нужный вопрос и формат
в зависимости от типа квитанции.

## Шрифты

Шрифт квитанции — **TinkoffSans** — встроен в PDF как subset: внутри только
глифы исходного текста и нет таблицы Unicode-сопоставления, поэтому новый
текст встроенным шрифтом отрисовать нельзя.

В проект добавлены полные файлы TinkoffSans — два начертания:

| Файл | Начертание | Где применяется |
|------|------------|-----------------|
| `TinkoffSans-Regular.ttf` | Regular | дата, суммы, имена, карта, № квитанции |
| `TinkoffSans-Medium.ttf`  | Medium  | жирная сумма «Итого» (16pt) |

Размеры и цвета берутся из исходного span документа без изменений.

| Поле | Размер | Цвет | Начертание |
|------|--------|------|------------|
| Дата и время | 8pt | `#909090` (серый) | Regular |
| Итого сумма | 16pt | `#333333` | **Medium** |
| Значения строк (сумма, имена, карта, банк) | 9pt | `#333333` | Regular |
| Квитанция № | 9pt | `#333333` | Regular |

> Знак ₽ (`ALSRubl`) и подписи строк остаются из оригинала — бот их не трогает.

## Архитектура бота

### Состояния диалога

```
WAITING_PDF → STEP_DATE → STEP_TIME → STEP_AMOUNT →
STEP_SENDER → STEP_CARD → STEP_RECIPIENT → STEP_BANK →
STEP_RECEIPT → CONFIRM → WAITING_PDF
```

### Ключевые классы

#### `TextSpan`
Один текстовый блок из PDF:
```python
@dataclass
class TextSpan:
    page_num: int       # номер страницы
    span_idx: int       # глобальный индекс
    bbox:     tuple     # (x0, y0, x1, y1) — рамка текста
    origin:   tuple     # (x, y) — точка базовой линии
    text:     str       # исходный текст
    font:     str       # имя шрифта (напр. 'TinkoffSans-Regular')
    size:     float     # размер в pt
    color:    int       # цвет (packed 0xRRGGBB)
    flags:    int       # флаги: bold=16, italic=2
```

#### `ReceiptFields`
Индексы найденных полей:
```python
@dataclass
class ReceiptFields:
    datetime_idx:  int | None  # дата+время
    itogo_idx:     int | None  # сумма Итого
    summa_idx:     int | None  # сумма Сумма
    sender_idx:    int | None  # отправитель
    card_idx:      int | None  # карта или телефон получателя
    recipient_idx: int | None  # получатель
    bank_idx:      int | None  # банк
    receipt_idx:   int | None  # номер квитанции
    card_kind:     str         # "card" (шаблон 1) или "phone" (2/3)
```

#### `UserSession`
Данные сессии пользователя:
```python
@dataclass
class UserSession:
    doc_path:  str           # путь к временному PDF
    spans:     list          # все блоки
    file_name: str
    fields:    ReceiptFields # найденные поля
    values:    ReceiptValues # введённые пользователем значения
```

### Определение полей (`detect_receipt_fields`)

Поля находятся автоматически по содержимому:
- **Дата/время**: по regexp `\d{2}\.\d{2}\.\d{4}\s+\d{2}:\d{2}:\d{2}`
- **Квитанция №**: по regexp `Квитанция\s+№`
- **Остальные**: поиск span справа от метки (Итого, Сумма, Отправитель и т.д.)
- **Карта / Телефон**: ищется метка «Карта получателя»; если её нет —
  «Телефон получателя». Результат пишется в `card_idx`, тип — в `card_kind`
  (`"card"` или `"phone"`).

### Замена текста (`apply_edits`)

```
1. Открыть PDF
2. Для каждой страницы с изменениями:
   a. add_redact_annot() — пометить старый текст
   b. apply_redactions(graphics=NONE) — стереть только текст,
      фон и линии-разделители сохраняются (один раз на страницу!)
   c. Для каждого изменения:
      - pick_font_file() → выбираем Golos Text Regular или Medium
      - вычисляем X с учётом выравнивания, Y = origin (базовая линия)
      - TextWriter.append() + write_text() → пишем текст
3. Сохранить в байты
```

### Выбор шрифта (`pick_font_file`)

```
Если имя исходного шрифта содержит medium/bold/semibold/black
   или установлен флаг bold (16) → TinkoffSans-Medium.ttf
Иначе                                → TinkoffSans-Regular.ttf
```

### Позиционирование и выравнивание

- **По вертикали** — текст ставится по базовой линии `span.origin[1]`,
  а не по нижней границе рамки (иначе строка «съезжает» вниз).
- **По горизонтали** — значения правой колонки (суммы, имена, карта, банк)
  выровнены по правому краю: `X = bbox.x1 − ширина_текста`.
  Подписи левой колонки (дата, № квитанции) — по левому краю `bbox.x0`.
- Признак правой колонки: `bbox.x0 > ширина_страницы / 2`.

| Команда | Описание |
|---------|----------|
| `/start` | Запустить бота |

## Технические детали

### Почему TextWriter, а не insert_text

`insert_text` с `fontfile=` использует однобайтовую кодировку (WinAnsi),
которая не поддерживает кириллицу — символы рендерились как точки.

`fitz.TextWriter` создаёт Type0 шрифт с Identity-H (Unicode) кодировкой,
что гарантирует корректный рендеринг кириллицы, латиницы и цифр.

### Почему не используется встроенный шрифт PDF

Шрифт TinkoffSans встроен в квитанцию как subset: в файле только глифы
исходного текста и нет таблицы `cmap` (Unicode → глиф). `fitz.Font` не может
сопоставить новые символы с глифами, поэтому используются полные файлы
шрифта `TinkoffSans-Regular.ttf` / `TinkoffSans-Medium.ttf`, лежащие в репо.

### Порядок apply_redactions

`apply_redactions()` вызывается **один раз на страницу** после всех
`add_redact_annot()` — иначе координаты последующих аннотаций смещаются.
Параметр `graphics=PDF_REDACT_LINE_ART_NONE` сохраняет фон и линии квитанции.

## Известные ограничения

- ₽ знак (`ALSRubl`) не редактируется — он остаётся из оригинала.
- Бот рассчитан на шаблон квитанции Т-Банка. Другие PDF работают в общем
  режиме, но автоопределение полей может не сработать.
